ANWEISUNGEN ZUM AKTUALISIEREN DER BEDIENUNGSANLEITUNG
=====================================================

WICHTIG: Diese Datei bei jeder Aktualisierung der Bedienungsanleitung einlesen.
Die Bedienungsanleitung wird NUR auf ausdrückliche Anforderung des Benutzers
aktualisiert, nicht automatisch als Teil anderer Änderungen. Aktualisiert
werden Bedienungsanleitung.md und die daraus generierte Bedienungsanleitung.html
(und nur diese). Eine PDF-Variante wird seit V1.47 NICHT mehr erstellt und auch
nicht mehr verteilt – alle Schritte in dieser Reihenfolge ausführen.


VORAUSSETZUNGEN
---------------
- pandoc (konvertiert Markdown -> HTML)
- LuaLaTeX / lualatex-math.sty / TeX Live werden für die PDF NICHT mehr benötigt.


SCHRITT 1: Markdown aktualisieren
---------------------------------
- "Bedienungsanleitung.md" inhaltlich an den aktuellen Stand von
  app.js / index.html / style.css anpassen (z. B. neue Funktionen,
  geänderte Bedienung, Spaltenanzahl, Menü-Reihenfolge).
- Versionsnummer im Titel (Zeile mit "## Anwesenheits-Dashboard (Version X.Y
  vom TT.MM.JJJJ)") und in Kapitel 9 (Versionsinfo) anheben.
- Datum = aktuelles Tagesdatum, Version = alte Version + 0.1.


SCHRITT 2: index.html anpassen
------------------------------
- Versions-Fußzeile unten anheben, Format:
    <div id="version" class="version">Version X.Y vom TT.MM.JJJJ · ...</div>
- Cache-Buster in style.css und app.js erhöhen (damit der Browser keine alte
  CSS/JS-Datei aus dem Cache nimmt):
    style.css?v=1.27  ->  style.css?v=1.28  (jeweils +0.01)
    app.js?v=1.30     ->  app.js?v=1.31
- Versionsnummer und Datum müssen in Bedienungsanleitung.md UND index.html
  IDENTISCH sein.


SCHRITT 3: Markdown -> HTML (pandoc)
------------------------------------
Header-Fragment mit App-Look anlegen (falls noch nicht vorhanden unter
/tmp/opencode_pdfbuild/html-header.html):

    cat > /tmp/opencode_pdfbuild/html-header.html <<'EOF'
    <style>
    body { font-family: -apple-system, 'Segoe UI', Roboto, Arial, sans-serif; max-width: 800px; margin: 0 auto; padding: 16px; color: #1C2128; line-height: 1.5; font-size: 15px; }
    h1, h2, h3 { color: #185FA5; line-height: 1.25; }
    h2 { border-bottom: 1px solid #E6E7EB; padding-bottom: 4px; }
    code, pre { font-family: Menlo, Consolas, monospace; background: #F4F5F7; border-radius: 4px; font-size: 0.9em; }
    pre { padding: 10px 12px; overflow-x: auto; }
    code { padding: 1px 4px; }
    table { border-collapse: collapse; width: 100%; }
    th, td { border: 1px solid #E6E7EB; padding: 6px 8px; text-align: left; vertical-align: top; }
    th { background: #F4F5F7; }
    hr { border: none; border-top: 1px solid #E6E7EB; margin: 24px 0; }
    a { color: #185FA5; }
    blockquote { border-left: 3px solid #E6E7EB; margin-left: 0; padding-left: 12px; color: #6B7280; }
    </style>
    <meta name="theme-color" content="#185FA5">
    EOF

    pandoc Bedienungsanleitung.md -o Bedienungsanleitung.html --standalone \
      --include-in-header=/tmp/opencode_pdfbuild/html-header.html \
      --metadata title="Bedienungsanleitung Anwesenheits-Dashboard"

Die HTML-Fassung ist die EINZIGE verteilte Form der Bedienungsanleitung und
die PRIMÄRE Anzeige in der App (Footer-Link in index.html). Sie wird vom
Service Worker mit cache-first (offline-first) geladen und steht zusätzlich im
SW-PRECACHE (Offline).


SCHRITT 4: Prüfung
------------------
    grep -q "Version X.Y vom" Bedienungsanleitung.html && echo "Version OK"
    # sowie visuelle/semantische Kontrolle des Inhalts im Browser.


ALLGEMEINE HINWEISE
-------------------
- Nach Abschluss: Bedienungsanleitung.md und Bedienungsanleitung.html
  zusammen committen (die PDF-Datei wird nicht mehr erstellt bzw. gepflegt).
- Keine PDF-Variante mehr erzeugen (weder pandoc noch lualatex).
